# Prototype Instructions

## 萤火足迹 product decisions

- Latest product direction supersedes the earlier three-theme requirement: the web app now uses one visual system with white/light and dark/night appearance modes. Share all data across modes; preserve retired-theme assets and historical evidence. Map old night preferences to dark, all other old preferences to light.
- Map-first China → province → city → county experience. Use real administrative boundaries rather than the illustrative map in the generated concepts.
- Records belong to cities; multiple visits to the same city remain separate memories.
- First version is a private browser-based prototype. Label sample records and sample attractions clearly. Do not claim online accounts, automatic tourism APIs or cloud photo storage exist.
- Future mobile app must support both Android and iOS; preserve functional responsive mobile layouts and separate platform storage/photo-permission capabilities from domain logic. See docs/product-direction-2026-10-24.md for the latest requirements.
- New photo architecture must retain the exact imported original locally, with separate derived thumbnails/previews. Original export/download must not re-encode the file. Never claim the current 1100px JPEG copies are originals or can recover originals that were discarded. Plan a storage abstraction for future opt-in cloud migration; no server or automatic upload is authorized now.
- Memoir map animation is implemented on the web: ordered visits joined by luminous lines, with a firefly moving between stops. Label these as memory connections, not GPS/navigation traces. Preserve repeated visits, visitOrder for tied dates and tripName grouping; do not present independent trips as a factual single itinerary.
- Photo-map collage is implemented on the web: user-selected photos clipped to real province/city/district boundaries, with non-destructive positioning and crop adjustments. Photo artwork and map-lighting/travel facts are separate. Composite export is a new 2400px PNG, not an original-photo export.
- User confirmed on 2026-10-25 that photo-map collages must support both selectable modes: one cover photo per region and multiple photos collaged within one region. Both are in scope, not mutually exclusive product alternatives or a deferred multi-photo option. Mode switches must preserve photo selections and layout/crop settings without modifying original files.
- User approved the five highest-priority audit fixes: prevent concurrent-tab lost updates, preserve drafts, restore backups, edit travel records/photos, and unify footprint displays.
- Data now lives in IndexedDB. Preserve legacy localStorage snapshots and migrate without resetting user content. Use transactional mutators on latest stored data, never overwrite from stale React state.
- Since 2026-10-26, IndexedDB v2 adds photos and layouts stores. New records use photo:ID references and originals live as independent Blob entities with SHA-256; legacy inline images remain readable. Unassigned photo-library originals are durable and included in backups. Do not auto-delete originals on travel deletion: drafts, other records, collages and checkpoints may still reference them.
- Backups are now binary .yhf archives containing a bounded JSON manifest, original/preview payloads and per-file hashes. Export/createArchive and readArchive share the format. Restore assets/records/layouts atomically, never overwrite a conflicting same-ID photo. Old JSON imports stay supported but cannot restore standalone photo references. Preserve raw legacy text on startup rescue.
- Saving and importing share geographic/record rules in backup.js. src/regions.json is a compact projection of public/maps/index.json and download-maps.mjs regenerates both. New saves check a conservative manifest capacity budget; do not replace this with blind truncation or claim unlimited storage.
- Current web verification is documented in qa/features/acceptance.md. Android/iOS native file adapters, permission/system-album flows and real-device tests are not yet implemented/verified; do not describe a responsive browser test as an installed app test. No cloud is configured.
- Record versions must not repeat after delete-and-restore. Conflicts preserve drafts and require an explicit action; restored backups never silently override same-ID data in merge mode.
- Keep the audited secondary issues (year grouping, full routing, first-use demo separation, dense mobile labels) separate from the five implemented fixes. Do not claim the whole audit is resolved.
- For cross-computer handoff, read `迁移到新电脑.md`. Keep runtime paths portable; browser test executables can be selected with CHROME_PATH and the design reference is bundled in docs/design-reference.png. Never treat browser IndexedDB records as part of the source archive; private user content must be explicitly exported/imported through the app.
- User approved a new public GitHub repository named yinghuo-footprints and a public web-only showcase. Target owner is the verified connected account luojiu-9999. Publish only this app, not the parent worktree; never publish personal backups/photos, credentials, caches or runtime data. GitHub repository creation/Pages administration are not available in the current connector, so confirm actual remote existence and permissions before claiming upload/deployment. See docs/github-pages.md; GitHub Pages build uses /yinghuo-footprints/ while local build stays at /.

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.
