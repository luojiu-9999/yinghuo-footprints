# 萤火足迹

以中国地图点亮为入口的私人旅行记录网页。中国 → 省 → 市 → 区县，旅行按城市归档，同城多次到访各自独立记录。React 19、Vite 6、ECharts、IndexedDB；目前没有账号、云同步或自己的服务器，也尚未生成 Android / iOS 安装包。

## 2026-10-26 已实现

- 同一套界面，仅保留「白色模式 / 暗夜模式」。原夜间偏好映射到暗夜，其余旧主题映射到白色，不重置旅行数据。
- 新照片的原文件作为独立 Blob 保存于本地照片库；记录只保存 photo:ID 引用。另生成最长边1600像素的JPEG预览，列表/地图/动画使用预览，不覆盖原图。原图导出前校验 SHA-256，下载文件与选入文件字节一致。
- 相册大图和照片地图裁切区均可下载原图。旧版压缩图与示例图片明确标为「旧版图片」，不能还原原片。旧内嵌照片继续可用，不批量重写或丢弃。
- 回忆录新增「萤火旅线」：按日期、同日顺序串联到访，保留重复城市；萤火虫沿发光线移动，可暂停、回到起点、拖动进度、变速或显示静态连线。可选年度回忆串联或用户填写的旅行分组，不冒充 GPS 或导航轨迹。
- 新增「照片地图」：全国按省、省内按市、城市按区县的真实边界填图；支持单图填充和区域内多图拼贴（最多8张、1/2/3列），分别保留选择、排列及平移/缩放裁切参数。布局自动保存，可导出2400×1680 PNG，不改原图或旅行统计。
- 照片地图可单独导入原图；即便尚未关联旅行或填充区域，也保留在本地照片库并纳入新备份。
- 新版 .yhf 备份把清单、原文件、预览分别存放，不再把原图编码进单个JSON。逐张校验后在同一数据库事务内恢复旅行、照片与布局；合并保留当前同ID记录，替换须确认并保留可撤销快照。
- 启动失败有救援页面：可导出原始文本、尝试导出可读原图备份或恢复有效备份，不要求先清除旧数据。
- 保存和恢复共用记录校验，101个景点可正常往返；校验省市县归属和手动足迹路径，兼容直辖市、港澳及省直管城市。全局新增记录要求明确选择省市，不再默认杭州。
- 保留草稿自动保存、编辑照片/封面、多标签并发新增与同记录版本冲突保护。旧 localStorage 原始副本继续保留。

## 使用与数据安全

1. 在地图选择省、市或区县，添加到访、备注、照片；或从「城市记录」新增。
2. 在右上角外观按钮切换浅色/暗夜；「我的设置」可导出/恢复备份、查看草稿或移除示例。
3. 到「回忆录 → 萤火旅线」播放回忆；需要单次旅行分组时，在记录编辑表单填写相同的旅行分组名，并按需设置同日顺序。
4. 到「照片地图」选择地图层级、填充区域和照片。裁切面板可选照片并调整位置/缩放；两种模式互不清空，照片分配不证明实际到访。

首次打开含杭州、大理两条示例，可明确移除。自动景点仍为内置示例，没有接旅游API。

原图保存在当前设备的当前浏览器站点中，不等同系统相册或永久备份。清除站点数据、浏览器卸载或系统回收可能丢失内容；请定期把 .yhf 备份保存到应用之外。删除旅行记录会保留地图足迹和本地照片库文件，不自动清理照片，以免破坏其他记录、草稿、拼贴或恢复快照。

当前保护边界：每条记录8张照片，单张原图100 MiB，地点最多10000个、到访天数1–365。新原图备份没有旧版100 MiB总文件截断，但仍受设备空间和内存限制；清单上限32 MiB，写入前有保守元数据容量保护，不能宣称无限容量。恢复旧版JSON仍限制100 MiB；更大的旧文件应在原环境升级后导出 .yhf，或在保全原文件后专门分批迁移，不能直接删数据。

JPG/PNG/WebP及HEIC/HEIF可保留原文件。预览能力取决于浏览器；无法解码时保留原文件和占位预览。照片可能含定位等元信息，原文件导出会保留这些内容，请谨慎分享。Android / iOS 文件权限、系统相册、后台与真实设备容量尚待封装后验证；没有实现云上传，也没有自动删除本地副本。

## 地图、素材与当前边界

地图为本地 DataV GeoAtlas GeoJSON，约3237个有效地区。部分地区没有下一级边界，明确提示缺失，不编造轮廓。原始来源与下载情况见 public/maps/download-report.json。正式发布前还需核实地图数据、展示与导出的适用要求，不声称已满足正式商用地图要求。

内置风景、品牌和历史设计稿保留于 public/assets，采用已有 ImageGen 素材；普通图标来自 Phosphor。原始个人主页及其他项目未修改。历史三主题截图和旧审计报告是当时的证据，不代表当前界面或当前缺陷状态。

跨年报告/重叠天数口径、首次示例与个人数据进一步隔离、完整浏览器路由恢复，以及密集手机地图标签等，仍属于未完成的后续工作。

## 配置、测试和迁移

新电脑先阅读「迁移到新电脑.md」。Windows 可运行 setup.ps1 安装锁定依赖、构建和测试，再运行 start-preview.ps1；脚本验证页面实际就绪后才报告成功。Node.js 22.12+，当前在Node.js 24验证，支持通过 setup.ps1 -NpmCli 指定已存在的 npm-cli.js。

GitHub网页展示配置见 [GitHub Pages部署说明](docs/github-pages.md)。`npm run build:pages` 按 `/yinghuo-footprints/` 子路径构建；工作流仅发布静态网页，不启用服务器、云同步或手机安装包。远端创建/部署成功前，不将预期地址当作已上线地址。

标准命令：

    npm ci
    npm run build
    node --test tests/backup-domain.test.mjs tests/reliability.test.mjs tests/sites-worker.test.mjs
    npm run dev -- --host 127.0.0.1 --port 4173 --strictPort

网页：http://127.0.0.1:4173/ 。仅是本机预览，进程关闭后需要重启。依赖已安装的当前环境可用 node .tools/package/bin/npm-cli.js 代替全局 npm；.tools 不随源码包迁移。

保持开发服务器运行后，使用独立测试浏览器执行：

    node scripts/verify-ui.mjs
    node scripts/verify-priority-fixes.mjs
    node scripts/verify-features.mjs

构建后可另运行 `node scripts/verify-production.mjs`，在临时4174端口验证编译后的页面，结束会关闭该临时服务。

脚本自动寻找 Chrome / Edge / Chromium，或使用 Playwright 浏览器；可设 CHROME_PATH。必要时使用 npx playwright install chromium 配置测试浏览器。测试不读取真实浏览器旅行数据。新功能验收见 qa/features/acceptance.md，历史优先修复见 qa/priority-fixes/acceptance.md。

新 .yhf 备份包含已保存旅行、手动点亮、本地原图库（含未关联照片）与拼贴布局；不含未保存草稿文本、主题偏好或撤销快照。迁移前先保存要保留的草稿。原图不会出现在项目源码压缩包中，必须单独从应用导出迁移。

Android/iOS与长期存储方向见 docs/product-direction-2026-10-24.md，当前网页实现状态以本 README 和最新验收为准。未发布网站。
